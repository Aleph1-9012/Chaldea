# Tsugumori / Oblique ligatures

Five rows of connected, slanted glyphs contain smaller letter fragments. Each typed character advances one glyph in reading order. Its joints shift into their alternate positions, its smaller fragments follow, and a red highlight marks the active glyph. Deleting reverses this sequence. The browser and native QML component share the drawing and motion rules. Enter or Unlock replays the red curtain.

The composition combines narrow, medium, and wide characters, with nested fragments sized to fit each character. Fine ligatures connect actual joints on neighbouring forms. A consistent oblique angle, muted ink, and red accents tie the different structures together. The resting artwork stays fixed. After all 27 glyphs have advanced, further input begins another pass through the same sequence. The browser canvas renders at least three pixels per CSS pixel and follows changes in its display size. Native artwork uses a 756-pixel canvas for the same 252-unit drawing.

This is an interactive visual study. It does not authenticate users, create a session lock, or unlock the desktop. Use dummy text in its demo field.

## Run

Save each file from the output selector into a widget folder, preserving the displayed file names and subfolders. Keep `Widget.qml`, its QML helpers, and `GlyphArt.js` together. With Quickshell 0.3.0 and Qt 6.11.2 installed, run:

```sh
qs -p /absolute/path/to/the/widget-folder/shell.qml
```

The launcher opens a regular, resizable window. It uses Qt Quick, Qt Quick Controls Basic, and Qt Quick Layouts. It does not change desktop configuration or connect to authentication services. To embed the component in a QML layout:

```qml
import "./oblique-ligatures" as Glyph

Glyph.Widget {
    width: 354
}
```

The artwork fits above the input panel at narrow widths. The example window scrolls when its content is taller than the available space. JetBrains Mono and Noto Sans CJK JP are used when installed, with system font fallback. No fonts, images, remote assets, or additional native libraries are bundled.

## Interaction and settings

Click the demo field or use Tab to focus it. Type, paste, use Backspace/Delete, or replace a selection. Input is limited to 64 UTF-16 units, matching browser string length. A committed edit is replaced with `x` placeholders. The artwork depends only on length; typed characters and their hashes never select its geometry. Input and selection stay in memory for this component's lifetime.

Enter and Unlock replay the curtain when the input is nonempty. Empty submission focuses the field and shows a prompt. Editing during replay dismisses the curtain. When replay finishes, the pattern and current length remain. Clearing the field returns to the original drawing.

Input transition sets the response speed from 80 to 350 ms, with a default of 220 ms. Motion follows the latest input with damping and no overshoot. Rapid typing retains forward velocity; deletion changes direction immediately. Pasting and clearing settle to the requested length without queuing individual key animations. Red emphasis adjusts the red tint from 65 to 100 percent. Input animation turns movement and the curtain transition on or off.

Appearance and timing changes preserve the input length. The browser also honors reduced-motion preferences. In native QML, use the animation setting to disable transitions. Hidden native components stop their pending movement and replay timers. Copied QML and individual file downloads include the same settings snapshot.

## Host integration

`inputLength`, `phase`, and `previewing` expose the component's current visual state. `setInputLength(length)` supplies a bounded dummy length without passing text. `focusInput()` focuses the demo field. `replay()` runs the preview, and `previewRequested(length)` reports that action with only the current length. A host can observe these for visual coordination; the component performs no authentication.

`GlyphArt.js` contains the drawing and damped motion functions shared by the sandboxed browser preview and QML. This widget has its own `GlyphWidget.qml`, driven by frame updates, so the other glyphs keep their existing input behavior. The QML template is generated by Chaldea's shared frontend generator.
